# 16 节概要设计模板

**使用方式**：写文档时按以下指南逐节填充。模板 16 节及顺序固定：某节不适用时保留标题写「不涉及」或「无」，不删除标题，不新增模板未列出的顶层编号章节。第 10 节「工程决策清单」为检查清单，子节逐项保留，涉及则写设计、不涉及写「不涉及」，不允许留空。

---

## 1. 背景

说清现状和痛点——现在怎么做、哪里有问题、不改会怎样。2-3 段即可，不要写成需求文档。**如有产品需求文档或原始需求，附文档链接**（wiki / docx），便于追溯。

## 2. 目标

可衡量的具体目标，bullet list。每一条写完之后能验证——「接口迁移完成」不是目标，「调用方无感切换、新旧报文逐字段一致」才是。**性能类指标也写在这里**，如「分页查询响应时间 < 500ms」。

## 3. 价值

表格：价值维度 + 说明。说清业务收益，不是技术收益。

| 价值 | 说明 |
|---|---|
| xxx | xxx |

## 4. 架构编排

编号步骤，宏观调用链。谁调谁、谁接谁、数据怎么流。3～5 步说清主链路。

## 5. 业务流程编排

Mermaid flowchart + 兼容约束 + 业务范围边界。

- 流程图放前面，用 `flowchart TD`，动作 `[]`、判断 `{}`、条件 `-->|标签|`
- 兼容约束紧跟其后，写「不做什么」清单（bullet list）
- **业务范围边界**单独列出：本功能明确不做的事（如「指令管理只维护配置，不实现拦截执行逻辑」）

**如果接口迁移/改造类方案**：必须同时画出旧流程和新流程两张图对比。

## 6. 状态流转

有状态机时写状态图或状态表（状态 + 触发条件 + 目标状态）。没有则写「无状态变更」。

## 7. 接口定义

每个接口六件套：

1. 地址 — HTTP 代码块
2. 请求规格 — 字段表（字段、类型、必填、校验规则、说明）+ JSON 示例
3. 返回规格 — 场景-返回对照表
4. 内部查询逻辑 — SQL/ORM 条件
5. 下游推送参数 — 表必须有「赋值来源」列
6. 处理规则 — 校验顺序、业务规则、特殊情况、日志记录规则（bullet list）

**文件类接口（导出/导入）**：单独写文件命名、表头字段表（含「数据来源 + 转换规则」两列）、数量限制。

## 8. 数据库表设计

新建表写 DDL + 字段说明表。改表写 ALTER + 影响范围。索引要写清作用与取舍。不涉及写「不涉及数据库变更」。

## 9. 外部系统依赖

表格：对接系统 + 配合事项。每一项必须明确对方要做什么。

## 10. 工程决策清单

检查清单，子节逐项保留：**涉及则写清设计，不涉及写「不涉及」**，不允许留空。逐项过一遍确保不遗漏。

- **10.1 方案对比与取舍** — 存在多个候选方案时写对比表 + 选择理由；只有一个方案写「无多个候选方案」
- **10.2 模块分层与代码结构** — Controller / DTO/VO / Enum / Entity / Service 的建议命名 + 归属模块
- **10.3 业务范围边界（不做什么）** — 本功能明确不实现的事项
- **10.4 枚举与值域语义** — 关键枚举的取值与业务语义
- **10.5 国际化处理** — 词条编码、默认内容、降级策略
- **10.6 错误处理对照** — 场景 → 错误提示文案
- **10.7 缓存设计** — 是否加缓存、一致性处理、失效通知
- **10.8 MQ 消息事件设计** — 消息体、Topic、消费幂等、补偿机制
- **10.9 多线程使用思考** — 是否用多线程、事务内异步问题
- **10.10 数据一致性** — 主表与从表/日志的事务边界
- **10.11 定时任务（XXL-JOB）** — 是否需要定时/周期任务
- **10.12 刷数据 / 初始化 / 数据迁移** — 存量数据初始化脚本、核验方法
- **10.13 本地事务 & 分布式事务（含回滚方案）** — 事务边界、异常回滚、回滚动作
- **10.14 锁 & 分布式锁** — 并发控制策略、乐观锁 vs 分布式锁
- **10.15 幂等性设计** — 每个写操作的幂等策略
- **10.16 重试机制** — 重试/不重试的边界
- **10.17 配置开关** — 配置项开关及其生效条件
- **10.18 导出 / 文件类接口专项** — 文件命名、表头转换、导出限制

## 11. 测试方案设计

分组列出测试点：功能测试 / 异常测试 / 性能测试。设计文档里给出测试点，开发与测试可直接执行；性能测试给出量化目标。

## 12. 部署与上线方案

有特殊部署顺序、配置开关、灰度策略、回滚动作、上线前数据核验时写清。没有写「无特殊部署要求」。

## 13. 总体规划

表格：阶段 + 内容 + 完成标准。

**完成标准必须可验证**，不能写「完成开发」「完成测试」这种无法验证的表述。

## 14. 任务排期

表格：时间 + 任务 + 产出。按天或按阶段排。

## 15. 兜底方案

表格：异常场景 + 兜底措施。

每条措施必须可执行——写清楚谁在什么时候做什么操作，不写「及时处理」「视情况而定」。

## 16. 待确认事项

表格：编号 + 待确认项 + 影响。需求或代码无法确认、且影响实现的事项集中列在这里，便于评审与追踪。已能落在具体章节的细节仍在该节写「未确认」，此处只列系统性待确认项，不重复。

| 编号 | 待确认项 | 影响 |
|---|---|---|
| 1 | xxx | xxx |
