# 持久化、事务与安全

## 分层与事务

- Controller 负责边界校验、调用 Service 和返回协议结果；Service 负责业务规则、事务和外部调用编排；Mapper/DAO 只负责明确的数据访问。
- ID、编码、状态、租户和功能开关等业务决策在入口或 Service 完成，不把 mode、开关等决策变量下推给 SQL。
- 本地数据一致性写操作明确事务边界，事务保持短小。RPC、MQ、文件和长耗时计算不默认放入本地事务。
- 当编排层需要持有业务锁直到事务提交，或需要规避同类方法调用导致事务代理失效时，可以使用职责明确的 `XxxTransactionService` 承载原子写操作；普通 CRUD 不为放置 `@Transactional` 新增转发服务。
- 并发写入先检查唯一约束、幂等键、乐观锁和项目已有锁。只有存在真实竞争条件时加锁，并明确锁对象、粒度、顺序和超时。
- 状态流转集中维护允许关系、重复请求语义和终态规则。更新 SQL 携带期望旧状态或版本条件，并检查影响行数；禁止先查后无条件更新覆盖并发结果。
- 长流程需要固定业务口径时，在开始阶段生成带版本或任务标识的业务快照，后续查询、导出和异步处理基于该快照，并明确快照的生命周期与刷新策略。
- 数据库、API、DTO、枚举、MQ 消息和缓存结构变更前检查所有生产者、消费者及序列化兼容性，优先采用可向前、向后兼容的分阶段迁移。

## SQL 与 MyBatis

- SQL 必须参数化。MyBatis 值参数使用 `#{}`；动态表名、列名、排序字段等无法绑定的标识符必须由可信白名单映射，禁止直接拼接用户输入。
- 明确选择需要的列，避免 `SELECT *`。查询必须考虑逻辑删除、租户边界、数据权限和软删除条件。
- 避免 N+1 和循环内数据库调用，优先批量查询后构建 Map。批量与 `IN` 大小根据数据库和驱动限制分段。
- 对业务唯一性使用数据库唯一约束兜底，应用层预检查只改善提示，不能替代并发正确性。
- 索引依据查询模式、选择性、排序、覆盖性、写入成本和执行计划设计；不按 Join 表数量、固定行数或固定字段长度机械判断。
- 分页、排序、模糊查询和聚合必须评估边界与性能。分页越界、空值和总数行为遵循现有 API 契约。
- 数据订正、删除和结构迁移先用只读查询确认范围，并采用项目认可的备份、灰度和回滚方案。

## 数据模型

- DO/DTO/BO/VO/Query 等名称和边界遵循项目已有约定；只有字段、生命周期、权限或外部契约存在真实差异时转换，不创建重复模型。
- 字段类型表达真实的空值、范围、精度和时区语义。DTO、DO 的可空字段可使用包装类型；明确非空的内部值可以使用基本类型。
- 新表字段、主键、审计时间、逻辑删除和租户列遵循项目数据库规范，不强制所有表使用同一模板。
- 精确小数使用 `decimal`；字符串长度、字符集、外键、存储过程和索引命名遵循项目架构与数据库版本，不作为 Java 通用硬规则。

## 输入、权限与输出

- 在系统边界校验必填、范围、格式、长度、枚举、分页、批量大小和排序字段；校验规则应与业务契约一致。
- 访问用户或租户所属资源时校验资源归属和水平权限，不能只校验是否登录或只依赖前端隐藏。
- 权限规则复杂且被多个入口复用时，集中把请求范围收敛为当前用户允许范围；缺失身份、组织或归属信息时默认拒绝，并明确 `null`、空集合与全量范围的不同语义。
- 输出到 HTML、SQL、Shell、URL 等不同上下文时使用框架提供的对应编码或绑定能力，禁止用一个通用字符串替换 helper 处理所有注入风险。
- Web 项目使用框架现有 CSRF 机制；外部重定向解析规范化后的目标并校验协议、主机和允许范围。不得默认新增手写安全实现。
- API 错误码、成功码、空集合、空值和超大整数表达遵循项目现有公共协议，不在技能中固定为某一公司标准。

## 敏感信息与依赖

- 新增代码不得明文暴露密码、密钥、Token、证件号、银行卡号等敏感信息。日志、异常、响应和 `toString` 均需考虑泄露风险。
- 安全脱敏优先复用项目或框架能力，不为单个字段创建新的通用安全工具。
- 新增生产依赖前检查项目已有能力、维护状态、许可证、安全漏洞、包体积和传递依赖；不得只为简单 helper 引入依赖。
