# C# 测试、验证与代码审查

## 测试设计

- 测试应自动、独立、可重复，不依赖执行顺序、真实时间等待或不稳定的外部环境。
- 测试名表达可观察行为和条件，例如 `ShouldRejectRequestWhenPermissionIsMissing`，避免只复述被测方法名。
- 断言业务结果、状态变化、持久化影响或异常行为；禁止空断言、只执行不校验，或仅验证 Mock 调用次数。
- Mock 用于隔离外部依赖和证明关键副作用；不要为实现细节 Mock 每个内部调用，也不为测试扩大生产成员可见性或通过反射测试 private 实现。
- 覆盖正常路径、边界值、非法输入和重要失败路径。状态机、重试、时间转换、编号生成和并发控制等纯规则使用小而完整的矩阵测试。
- 时间、随机数、外部系统和调度通过项目已有抽象或可控边界稳定测试；目标框架支持且项目已采用时可使用 `TimeProvider`，不为简单代码引入抽象。
- xUnit、NUnit、MSTest、FluentAssertions、Moq、NSubstitute 等测试栈、目录和命名均沿用项目现状，不固定框架或版本。

## 何时补测试

- 修改业务规则、边界条件、错误处理、取消语义、事务、并发、序列化或已存在测试覆盖的行为时，说明建议新增或更新的相关测试。
- 纯格式、注释、生成文件或能由编译器/静态检查完全覆盖的低风险机械修改，可以不建议新增测试。
- 测试需要大规模重构公共测试基础设施、引入新依赖、访问真实外部环境或执行长耗时集成测试时，先说明范围并询问用户。

## 验证

- 先确定与改动匹配的最小验证方案，但不得主动运行 `dotnet build`、`dotnet test`、`dotnet publish` 或其他编译、测试、构建命令。说明推荐命令、验证目的和预期影响，并在获得用户明确确认后执行。
- 涉及多项目解决方案、集成测试、容器、数据库或网络依赖的验证不视为快速检查，必须单独说明预计范围和耗时。
- 发现项目配置跳过测试、过滤条件未匹配或目标框架不兼容时，报告实际未执行的原因；不得自动调整过滤器、环境变量或构建属性重跑，先询问用户。
- 验证失败时报告命令、关键错误和未完成项。验证通过后，只有新增修改、失败或未解决风险需要时才扩大范围。

## 代码审查顺序

按以下优先级给出可操作问题，格式类问题优先交给 `.editorconfig`、分析器和 CI：

1. 正确性：空值、取消、资源释放、边界、状态转换和异常语义。
2. 数据一致性：事务、唯一约束、并发 token、幂等、消息与数据库一致性。
3. 异步与并发：阻塞等待、未观察 Task、锁、并发集合、DI 生命周期、上下文和任务丢失。
4. 安全：授权、注入、敏感信息、反序列化、配置和依赖风险。
5. 兼容性：公共 API、DTO、枚举、数据库、消息、缓存和旧消费者。
6. 性能：N+1、同步 I/O、重复枚举、无界批处理、执行计划、资源上限和可观测证据。
7. 可维护性：主线、职责、抽象、命名、注释和项目约定。

审查结论必须关联具体文件和行号，说明触发条件、后果和可行修复方向。没有发现问题时明确说明剩余测试缺口或风险。
