# C# 异常、日志与可靠性

## 异常与取消

- 异常不用于正常流程控制。捕获范围与实际可处理能力匹配；禁止空 `catch`、吞掉未知异常或捕获 `Exception` 后伪造成功。
- 需要重新抛出当前异常时使用 `throw;`，不得使用 `throw ex;` 丢失堆栈。包装异常时保留 `InnerException` 并提供稳定的业务语义。
- `OperationCanceledException` 只在能够完成必要清理、转换边界语义或记录可操作信息时处理；请求或宿主取消通常应向上传播，不记录为系统故障。
- `finally` 不返回或覆盖业务异常。资源优先使用 `using`/`await using`，异步清理正确 await。
- 不向外部调用方泄露堆栈、SQL、连接串、Token、密钥或内部类型细节。

## 日志与可观测性

- 不得因无关需求删除、缩减、改写现有日志，或调整其级别和打印逻辑。
- 新增日志沿用项目的 `ILogger`、结构化字段、EventId、TraceId 和脱敏约定；不要使用 `Console.WriteLine`、`Debug.WriteLine` 或字符串拼接替代结构化日志。
- 仅记录定位所需字段。异常日志传入异常对象；不得通过 `ex.ToString()` 拼接后重复记录，也不得记录密码、密钥、Token、完整认证信息或无必要的完整实体。
- 同一异常由最能表达业务现场且负责处置的边界记录，避免 Controller、应用服务和基础设施多层重复打印。
- 外部调用记录稳定的目标标识、耗时、结果类别和必要定位字段；响应内容只在已获得且符合脱敏策略时记录。

## HTTP、消息、后台任务与重试

- `HttpClient` 使用项目已有的 `IHttpClientFactory`、typed client 或封装；明确超时、取消令牌和总请求预算，不在每次请求临时创建长期 `HttpClient`。
- 只有幂等操作或拥有可靠幂等键的操作，且故障确属瞬时可恢复时才重试。重试必须有次数上限、退避和抖动；沿用项目已有 Polly 或等价策略，不机械添加。
- HTTP、消息、缓存、文件等外部动作不默认放入长数据库事务。外部失败不得伪造成功，失败、补偿和最终一致性状态应体现在契约中。
- 数据落库与消息发布需要一致性时，优先使用项目已有 Outbox 或可靠消息机制；数据和消息记录在同一本地事务提交，提交后再投递并保留补偿扫描。
- `BackgroundService`、队列消费者和定时任务传递宿主停止令牌；需要 scoped 服务时创建短作用域，明确异常去向、重试、重复执行、幂等和优雅停机策略。

## 缓存与分布式协调

- 明确缓存是性能层还是权威数据源，说明来源、更新与失效顺序、一致性窗口和失败行为。
- 根据实际场景处理穿透、击穿和雪崩；不得默认增加布隆过滤器、分布式锁或多级缓存。
- Redis 或分布式缓存不可用时，根据数据库容量和一致性要求选择限流、快速失败、短期本地缓存或受控查库，禁止无条件把全部流量降级到数据库。
- 分布式锁使用项目已有可靠实现，校验所有权并安全释放；不得用固定值和无条件删除实现锁。
