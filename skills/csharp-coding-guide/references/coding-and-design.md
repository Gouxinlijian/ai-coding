# C# 编码与设计

## 流程与类型设计

- 入口方法按真实业务顺序体现校验、准备、核心处理和返回。公共成员负责业务编排；private/protected 成员承载完整、稳定的局部能力。
- 抽取方法应降低真实复杂度。单次属性赋值、简单判断或循环、参数转发及一次性读写通常内联；跨处重复或稳定业务边界才考虑公共 helper、接口或模式。
- 不为“以后可能”增加扩展点。接口用于多实现、替换边界、跨模块契约、代理或测试替身需求，不为每个服务机械创建接口。
- 一个类型围绕同一职责组织。新增抽象、DTO、Decorator、Strategy、Factory 或 extension method 前，确认存在真实变化点或清晰职责边界。
- 禁止新增循环依赖；不要用 `IServiceProvider`、延迟解析或静态容器掩盖新循环依赖。

## 可读性与语言特性

- 遵循 `.editorconfig`、分析器和项目格式化工具。没有项目约定时，以可读性优先，长表达式、复杂模式匹配、泛型和多个副作用按语义换行。
- `var` 仅在右侧类型明显、不会损害理解时使用；公开成员、复杂构造、数值和空值语义不清时显式写类型。
- 模式匹配、switch 表达式、集合表达式、primary constructor、required members 和 records 只在项目目标框架、团队约定和可读性允许时采用；不为使用新语法重写无关代码。
- LINQ 是查询表达，不是副作用管道。可能多次枚举的 `IEnumerable<T>` 在需要时物化；`ToDictionary` 明确重复 key 策略；输入和响应顺序有关时使用稳定顺序集合。
- 不可变公开契约优先使用只读接口或不可变类型；不要为了形式把内部可变集合全部包装成昂贵复制。

## 正确性、时间与资源

- nullable reference types 启用时修正根因，不用 `!`、空字符串或默认值掩盖不变量缺失。可空值类型的 `null`、`default` 和业务空值语义必须区分。
- 金额和精确小数使用 `decimal` 或按契约使用最小货币单位整数，不使用 `float`/`double`。比较 `decimal` 时不依赖二进制浮点习惯。
- 跨系统、导出、异步任务和审计时间使用 `DateTimeOffset` 或明确的 UTC 约定；本地日期和时区规则按业务契约处理，不依赖服务器默认时区或文化区域。
- 资源所有权清晰时使用 `using`/`await using`。不处置由 DI 容器、调用方或框架拥有的资源；实现 `IAsyncDisposable` 时正确级联异步释放。
- 字符串、数字和日期的解析与格式化明确使用项目约定的 culture；协议数据不得依赖当前线程 culture。

## 异步、并发与性能

- 异步 I/O 使用 `async`/`await` 并传递 `CancellationToken`。取消是“取消操作、取消等待或两者”的明确设计选择，不得假设所有 API 都会停止底层工作。
- 不使用 `.Result`、`.Wait()` 或 `GetAwaiter().GetResult()` 阻塞异步路径；不使用 `async void`，事件处理器除外。`Task.Run` 不用于包装服务端 I/O。
- `ValueTask` 仅在已证明高频同步完成可减少分配且调用方能正确消费时使用；默认使用 `Task`/`Task<T>`。
- 共享可变状态必须有线程安全策略。`lock` 使用 private gate，锁内不 `await`；异步互斥使用项目已有机制或明确的 `SemaphoreSlim` 生命周期。singleton 服务默认按并发访问审查。
- 先通过指标、执行计划、Profiler 或压测确认瓶颈，再引入缓存、并行、异步或复杂数据结构。后台扫描和补偿任务限制单批和单次总工作量。
