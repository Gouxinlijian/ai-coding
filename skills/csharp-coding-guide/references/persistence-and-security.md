# C# 持久化、事务与安全

## ASP.NET Core 分层与事务

- 端点层负责边界校验、授权上下文、调用应用服务和返回项目协议；应用服务负责业务规则、事务和外部调用编排；数据访问层只负责明确的数据操作。
- ID、状态、租户、功能开关和权限范围等业务决策在端点或应用服务完成，不把不透明的 `mode`、`flag` 或用户输入直接下推给 SQL/LINQ 查询。
- 本地一致性写操作明确事务边界并保持短小。RPC、消息、文件和长耗时计算不默认放入数据库事务。
- 当后台 singleton 或长任务需要 scoped 依赖时，使用 `IServiceScopeFactory` 创建短作用域。不得将 `DbContext` 注入 singleton、跨请求保存或跨线程并发使用。
- 并发写入先检查数据库唯一约束、业务幂等键、并发 token 和已有锁。发生 `DbUpdateConcurrencyException` 时按业务语义处理冲突、重新读取或明确失败，不机械无限重试。

## EF Core 与 SQL

- `DbContext` 以请求或工作单元为作用域，不并发执行同一实例上的操作。查询和保存异步 API 传递 `CancellationToken`。
- 只读查询按项目约定使用 `AsNoTracking()`；写流程只跟踪需要更新的实体。不要为“方便”先加载完整图再过滤，也不要盲目 `Include`。
- 避免 N+1 和循环数据库调用，优先批量查询、投影到所需列并在内存建立索引。分页、排序、模糊查询和聚合评估边界、索引与执行计划。
- 原始 SQL 使用参数化 API；动态表名、列名、排序字段等无法参数化的标识符必须映射到可信白名单，禁止拼接用户输入。
- 数据库唯一性由唯一约束兜底，应用层预检查只改善提示。迁移、订正和删除先用只读查询确认范围，并采用项目认可的备份、灰度和回滚方案。

## 模型、输入与授权

- Entity、DTO、Command、Query、Request、Response 等名称和边界遵循项目约定；只有字段、生命周期、权限或外部契约存在真实差异时转换，不创建重复模型。
- 模型准确表达可空性、范围、精度、时区和序列化语义。不要用 EF entity 直接暴露内部字段、导航属性或并发 token，除非项目明确将其作为契约。
- 在边界验证必填、范围、格式、长度、枚举、分页、批量大小和排序字段；复杂跨字段规则使用项目已有验证器或命名清晰的业务校验。
- 访问用户或租户所属资源时校验资源归属和水平权限，不能只校验是否登录或只依赖前端隐藏。复杂权限规则收敛为当前用户允许范围，缺失身份或归属信息时默认拒绝。
- 输出到 HTML、SQL、Shell、URL 等不同上下文时使用框架提供的对应编码或参数化能力；不得用一个通用字符串替换 helper 处理所有注入风险。

## 敏感信息与依赖

- 新增代码不得明文暴露密码、连接串、密钥、Token、证件号或银行卡号。日志、异常、响应和 `ToString()` 都要考虑泄露风险。
- 复用项目或框架的配置绑定、Secret 存储、数据保护和脱敏能力，不为单个字段创建新的通用安全工具。
- 新增生产依赖前检查项目已有能力、目标框架兼容性、维护状态、许可证、安全漏洞、包体积和传递依赖；不得只为简单 helper 引入包。
