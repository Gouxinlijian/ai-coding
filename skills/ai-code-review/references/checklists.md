# 分技术栈候选检查点

本文件列出评审时可用的候选检查点，按技术栈路由使用。清单只提示「可能要看什么」，
是否构成缺陷必须由第 4 节的上下文复核确认。不适用的条目直接跳过，不必逐条声明。

## Java 与 Spring

### 事务控制

- 数据变更（insert/update/delete）是否在事务内；多表或多步骤变更的事务边界是否正确。
- `@Transactional` 是否作用于可被代理的 public 方法；是否被同类方法直接调用导致失效。
- 事务范围是否过大，是否包含 RPC、HTTP 调用、文件 IO 或长耗时计算。
- 传播行为是否匹配业务语义（`REQUIRED`、`REQUIRES_NEW`、`NESTED`）；只读查询是否设置 `readOnly`。
- `rollbackFor` 是否覆盖受检异常；是否存在 catch 后不抛出导致无法回滚。
- 隔离级别是否满足并发要求；是否存在脏读、不可重复读、幻读风险。
- 多数据源下事务管理器是否覆盖实际写入的数据源；异步操作与事务的先后关系是否正确。
- 批量操作是否拆成合理批次；部分成功时的补偿或幂等策略是否明确。

### 异常处理

- 是否存在空 catch、捕获 `Exception`/`Throwable` 后不处理、或吞掉异常继续返回成功。
- 是否用返回 `null`/`false` 掩盖失败；调用方是否能区分「无数据」与「执行失败」。
- 异常信息是否包含必要上下文，是否泄露密码、令牌或个人信息。
- 是否保留异常链（`cause`）；自定义业务异常是否携带可判断的错误码。
- 关键操作是否配置重试与上限；重试是否幂等；失败后状态是否正确回滚或标记。
- 空指针、数组越界、类型转换等运行时异常是否有前置校验或 Optional 兜底。

### 并发与资源

- 共享可变状态是否有同步或不可变设计；锁的粒度、顺序是否可能死锁。
- 线程池是否为受管实例，队列与拒绝策略是否合理；是否存在在请求线程中创建线程池。
- 连接、流、`Cursor`、`ExecutorService` 是否在 finally 或 try-with-resources 中关闭。
- 是否设置超时与取消；阻塞调用是否可能耗尽线程。

### 数据访问

- 是否存在循环内查询（N+1）；是否可用批量或 join 替代。
- 分页是否带 limit；总数查询是否必要；深分页是否有性能风险。
- 查询条件是否命中索引；是否有全表扫描或隐式类型转换。
- 实体与库表字段是否一致；空值与默认值语义是否明确。

### 安全

- 鉴权是否发生在真实业务边界，而不是仅前端隐藏入口。
- SQL 是否全部参数化；是否存在 `${}` 拼接、字符串拼接或动态表名/排序字段。
- 外部输入是否校验与清洗；文件上传、反序列化、模板渲染是否可控。
- 凭据是否来自配置或密钥管理，是否硬编码；日志是否打印敏感字段。

### 设计与规范

- 类职责是否单一；是否存在循环依赖或分层穿越（Controller 直接操作 DAO 等）。
- 命名是否符合项目约定；是否存在魔法值、超长方法、重复代码。
- 复杂逻辑是否有注释说明「为什么」，而不是复述代码。
- 变更是否有对应测试；失败分支与边界条件是否覆盖。

### Spring 与其他框架

- 依赖注入是否以构造注入为主；是否存在字段注入导致的空指针或循环依赖。
- Bean 生命周期、初始化顺序、条件装配是否符合预期。
- 缓存使用是否处理穿透、击穿、雪崩；缓存与数据库的一致性策略是否明确。
- 配置项是否有默认值与校验；新增配置是否同步到各环境。

## 数据访问与 SQL

- `*Mapper.xml` 中 `${}` 是否用于可控值；动态排序、表名是否走白名单。
- 分页语句是否限制条数；是否存在无条件全表更新或删除。
- 多表写入是否在同一事务；影响行数是否校验。
- 字段与库表是否一致；新增字段是否有兼容旧数据的默认值。
- 手写 SQL 是否有注入风险；是否误用 `like '%...%'` 导致索引失效。

## 前端

- 副作用与依赖数组是否正确；是否存在闭包捕获过期状态或重复请求。
- Promise 是否被 await 或 catch；是否存在未处理的 rejection。
- `innerHTML`、`dangerouslySetInnerHTML`、`v-html` 是否用于不可信内容。
- 是否存在 `==` 比较、隐式类型转换、`any` 掩盖类型错误。
- 列表 key 是否稳定；条件渲染是否遗漏加载与错误态。
- 敏感信息是否进入前端包或日志；接口错误是否泄露后端细节。

## 其他后端语言

- Python：异常捕获范围、上下文管理器、可变默认参数、阻塞调用、类型注解与实际值。
- Go：错误是否被忽略、`defer` 与资源释放、goroutine 泄漏、context 取消、并发写 map。
- Rust：`unwrap`/`expect` 是否用于可恢复错误、锁中毒、异步阻塞。
- C#：`async`/`await` 是否漏等待、`IDisposable` 释放、取消令牌传递、可空引用。

## 数据与配置

- SQL 脚本是否可重复执行；是否有破坏性语句缺少备份或回滚。
- YAML/Properties 是否含明文密钥；默认值是否适合生产。
- Dockerfile 是否使用固定版本基础镜像、是否以 root 运行、是否复制了无关文件。
- 配置变更是否影响其他服务；是否同步更新文档与部署清单。

## 构建与依赖

- 是否引入 SNAPSHOT、`latest` 或未锁定版本；依赖是否与现有版本冲突。
- 是否新增不必要的依赖；许可证与安全公告是否需要核查。
- 构建脚本是否执行外部下载或不受控命令。
- 打包产物是否包含测试配置、密钥或调试开关。
