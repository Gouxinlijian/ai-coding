# 并发、线程与性能

本文件覆盖 Java 并发正确性、线程/线程池管理、异步编排与性能原则；事务内并发、数据库锁与消息幂等见[持久化、事务与安全](persistence-and-security.md)，RPC/MQ/缓存可靠性见[异常、日志与可靠性](exception-and-logging.md)。

## 可见性与共享可变状态

- 跨线程共享的可变字段通过 `volatile`、原子类（`AtomicInteger` 等）或正确的锁保证可见性与原子性；不得裸用 `static` 可变字段。
- 简单数值增减、递增计数使用原子类而非 `synchronized` + 普通 `int`；组合字段或多步操作原子性需锁或更高层原语。
- `synchronized` 锁定对象明确且稳定，锁内不调用外部未知代码，避免死锁；锁粒度与持有时间尽量小。
- `volatile` 保证可见性但不保证原子性；`++`、check-then-act 等复合操作不得依赖 `volatile`。
- 双检锁单例字段必须 `volatile`，或用枚举、静态内部类等更简方式。

## 并发容器与 ThreadLocal

- 优先使用 `ConcurrentHashMap`、`CopyOnWriteArrayList`、阻塞队列等并发容器；容器单个操作线程安全不等于复合操作（get-then-put）线程安全，复合操作用原子方法（`compute`、`putIfAbsent`、`merge`）。
- `HashMap`/`ArrayList` 不得被多线程并发读写，除非已由外部机制保证。
- `ThreadLocal` 在任务执行结束、尤其是被线程池复用时必须 `remove`，避免内存泄漏与脏数据；使用 try-finally 保证清理。
- 线程本地状态不得替代显式参数传递承载关键业务上下文。

## 线程与线程池

- 生产代码禁止每请求 `new Thread`；统一使用线程池或项目已有调度能力。
- 线程池必须显式设置核心/最大线程数、队列类型与容量、拒绝策略、线程工厂（命名）和超时；不得使用无界队列或默认无命名线程工厂。
- 拒绝策略根据业务选择：丢弃、抛异常、调用者执行或降级；不得静默丢弃关键任务。
- 阻塞队列类型匹配场景，明确有界容量避免无限积压；任务耗时与 I/O 特性决定是计算密集还是 I/O 密集线程池。
- 线程池不再使用时调用 `shutdown`/`shutdownNow` 并处理未完成任务；框架托管线程池由框架负责关闭。

## 异步编排

- 使用 `CompletableFuture` 等编排异步步骤，避免阻塞等待；不要用 `future.get()` 无超时阻塞异步路径。
- 异步链必须显式处理异常（`exceptionally`/`handle`/`whenComplete`），不得让异常被静默吞掉或导致任务悬挂。
- 异步回调/线程池中需要 Trace、MDC、租户等上下文时显式传递或包装，不得依赖 `ThreadLocal` 隐式传播。
- 明确异步结果是否需要等待、超时和取消；`Future` 超时使用带超时的 `get` 并处理 `TimeoutException` 与中断。

## 锁与乐观并发（与持久化协作）

- 需要跨方法或跨事务的业务锁时，使用项目已有分布式锁能力，校验锁所有权并安全释放；本地 `synchronized`/`ReentrantLock` 不解决跨实例竞争。
- 数据库层面的唯一约束、乐观锁、条件更新等并发手段见[持久化、事务与安全](persistence-and-security.md)；应用层锁只用于无法下沉到存储的短临界区。
- 多把锁固定获取顺序，避免交叉持锁死锁。

## 性能原则

- 先通过指标、执行计划、Profiler 或压测定位真实瓶颈，再引入缓存、并行、异步或复杂结构；不做无证据的"预优化"。
- 循环内避免重复数据库访问（N+1）、重复远程调用和重复昂贵计算，先批量/预取/缓存结果。
- 大对象、大集合和日志参数评估内存与序列化开销；缓存明确容量上限与淘汰策略，防止无界增长。
- `synchronized` 方法或粗粒度锁在高并发下是热点，评估是否缩小临界区或改用 `ConcurrentHashMap`/原子操作（锁粒度与持有时间见[可见性](#可见性与共享可变状态)）。
- 字符串拼接、正则预编译、集合初始容量等语言级优化见[Java 正确性](language-correctness.md)。
