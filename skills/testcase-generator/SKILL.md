# 测试用例生成

## 启用条件（硬性）

只有用户显式点名本技能才执行本流程：

- 说“用 testcase-generator”“使用测试用例生成器技能”“加载 testcase-generator skill”；
- 直接调用 `/testcase-generator`。

用户仅表达测试相关需求但没有点名本技能时，不加载、不套用本流程，可按普通任务处理，并可一句话询问是否启用。

启用后只做测试用例交付；代码修改、部署、缺陷修复不属本技能范围。

加载后第一件事是发起提问（需求文档、测试范围、输出格式、交付位置），在用户回答前不得生成任何用例，也不得自行假设需求内容。只有用户明确说“跳过提问、直接生成”时才可简化，且必须在交付说明中写明跳过了哪些确认。

## 目标

以用户提供的需求文档为唯一业务依据，产出**页面级功能与交互**的测试用例；用例标题与节点内容必须是人话，能直接看出测的是哪个页面、哪个功能、什么场景。

## 适配原则

- 不绑定业务域、技术栈、目录结构或知识库平台：先探测当前项目实际情况，再执行。
- 文中提到的检索、菜单、数据模型等只是“能力类别”，具体工具、命令与目录以当前环境实际提供的为准。
- 降级链：需求文档 → 页面与代码 → 知识检索 → 向用户确认。
- 文中的业务名词、目录名仅为说明性示例。

## 门禁

| 门禁 | 通过条件 | 未通过时 |
|---|---|---|
| 一、输入确认 | 已拿到需求文档（文件、链接或正文），并确认测试范围与输出格式 | 索要需求文档，不生成 |
| 二、理解确认 | 已列出功能清单与关键交互规则，并让用户确认过 | 复述理解并请用户确认 |
| 三、可读性自检 | 用例节点为功能语义描述，不含编号、优先级角标、证据代号 | 改写节点后重新自检 |

任一未通过时停在该步骤说明原因，不输出“示例版”“占位版”用例。

## 执行流程

### 步骤 1 收集输入

1. **要需求文档**。只接受三种来源：文件路径、在线文档链接、用户直接粘贴的正文。
   - 需求文档是唯一必需输入。没给文档时先索要，不得用代码或经验替代需求。
   - 链接读不到时说明失败并请用户提供正文或截图。
   - 读完复述：涉及哪些页面、每个页面的功能点、关键交互规则，请用户确认或纠正。
   - 只有用户勾选接口层，或明确要求用例对齐页面实现时，才索要代码地址；其他情况不要问代码路径。
2. **确认测试范围**（多选，默认只勾页面功能与交互）：

| 范围 | 说明 | 默认 |
|---|---|---|
| 页面功能与交互 | 页面上的字段、控件、按钮、弹窗、列表、提示、跳转、权限可见性 | 默认选中 |
| 接口层 | 请求路径、入参出参、状态码、幂等、异常码 | 不选，用户明确要才生成 |
| 兼容 | 浏览器、分辨率、终端 | 不选 |
| 性能 | 响应时间、并发、大数据量 | 不选 |
| 安全 | 越权、敏感信息展示、脱敏 | 不选 |

3. **确认输出格式与落点**：Markdown / XMind / 两者；默认 `docs/local/{业务范围}/`，项目已有用例目录则沿用。
4. **确认用例粒度**：默认“功能场景清单”（适合 xmind 与人读）；需要执行跟踪时可选“表格用例”。

用户回答“你决定/随便/都行”时采用上述默认值，并在交付说明中写明。

### 步骤 2 理解业务（内部完成，不作为交付物输出）

按 `references/business-grounding.md`：

- 以需求文档为起点，提取页面清单、功能点、字段与控件、校验与提示、按钮状态、流程与跳转、权限与可见性。
- 默认只依据需求文档生成。只有用户勾选接口层，或明确要求用例对齐页面实现时，才索要代码地址并在拿到后补齐；没有代码地址时不得自行检索用户未提供的仓库。
- 文档没写清、又不打算查代码的细节，列为待确认一次性问用户，不自行编造。
- 内部保留证据来源便于自查，但**不把证据表、代码行号、需求编号写进用例**。

### 步骤 3 设计用例

按 `references/design-methods.md`，以页面交互为主：

| 场景 | 关注点 |
|---|---|
| 表单与输入 | 必填、格式、长度、多选、默认值、只读与禁用、保存与取消 |
| 列表与搜索 | 默认排序、筛选、清空筛选、分页、空结果、加载态 |
| 弹窗与抽屉 | 打开与关闭、遮罩、二次确认、未保存离开提示 |
| 流程与状态 | 提交、审核、驳回、撤回、状态对应的按钮可用性 |
| 提示与反馈 | 成功提示、校验提示位置与文案含义、失败后的可恢复操作 |
| 权限与可见性 | 无权限时入口是否隐藏、只读态、数据范围 |
| 跳转与联动 | 页面跳转、返回后状态保留、字段联动显隐 |

只生成用户勾选的范围；接口层未勾选时，不写请求路径、入参、状态码。

### 步骤 4 生成交付物

按 `references/output-templates.md`：

- 默认用“功能场景清单”结构：业务对象或管理模块 → 功能 → 场景 → 操作 / 预期。同一对象的多个功能收在一个二级节点下，不要拆成多个二级节点。
- Markdown 默认写入 `docs/local/{业务范围}/`，文件名 `{需求名}-测试用例[-vMMdd_HHmmss].md`，同名不覆盖。
- XMind：`python {SKILL_DIR}/scripts/md_to_xmind.py <input.md> <output.xmind> [标题] [--tables expand|skip]`；清单结构直接转换即可。
- 用例标题规范：`{页面} - {功能} - {场景}` 或“在{页面}，{操作}时，应{结果}”。
- 禁止在节点中出现：`TC-xxx` 编号、`【P0】` 角标、`追溯：BR-x`、`E-C:112-113`、影响级别标签等内部标记。

### 步骤 5 自检与交付

按“自检清单”核对后交付，说明：

1. 需求文档来源与确认过的功能范围。
2. 生成的页面、功能、场景数量。
3. 文件路径与格式。
4. 未覆盖范围与待确认项。
5. 采用的默认值。

## 交付物结构

只包含以下内容：

- 用例主体（页面 → 功能 → 场景 → 操作/预期）。
- 简短的覆盖说明（覆盖了哪些页面与功能；未覆盖什么、为什么）。

不要包含：基本信息、执行约定、证据与业务理解确认单、测试数据准备、影响级别说明、方法罗列、代码行号。用户明确要求时才追加。

## 自检清单

- [ ] 用户显式点名本技能后才启动
- [ ] 已实际发起提问并收到用户回答，未自行假设需求或范围
- [ ] 已拿到需求文档，并复述确认过功能范围
- [ ] 测试范围与格式由用户勾选，未默认生成接口层用例
- [ ] 每个节点都能看出是哪个页面、哪个功能、什么场景
- [ ] 节点中无编号、优先级角标、证据代号、影响级别
- [ ] 操作步骤可执行，预期结果可判定
- [ ] 无“基本信息”“证据确认单”“测试数据准备”等内部章节
- [ ] 同时输出 md 与 xmind 时内容一致

## 常见错误

| 错误 | 处理 |
|---|---|
| 用户提到“测试用例”就自动执行 | 只有显式点名才启用 |
| 没给需求文档就开始写用例 | 先索要文档，不给不生成 |
| 默认生成一堆接口用例 | 默认页面功能与交互，接口层需用户勾选 |
| 用例里塞 `TC-xxx【P0】` 和证据代号 | 改为功能语义标题，内部信息不输出 |
| 交付物里放证据确认单和测试数据准备 | 这些只在内部使用 |
| 用例写成“验证功能正常” | 写清具体操作与可见结果 |
| 需求没写清就自行补规则 | 列为待确认，向用户提问 |
| 直接覆盖同名用例文件 | 加时间戳生成新版本 |
| 用户没选的范围也生成用例 | 只生成勾选范围 |
