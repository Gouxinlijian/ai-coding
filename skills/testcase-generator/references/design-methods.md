# 测试用例设计

默认面向页面功能与交互。方法只作为思考工具，最终产出必须是人能直接读懂的页面、功能、场景。

## 一、方法选择

| 需求特征 | 使用方法 | 落到页面上的关注点 |
|---|---|---|
| 输入有格式、长度、枚举限制 | 等价类 + 边界值 | 必填、格式错误、长度上限、下拉可选项、多选数量 |
| 多个条件组合决定结果 | 决策表 | 不同条件组合下按钮是否可用、提示文案、能否提交 |
| 有提交、审核、驳回、撤回 | 状态转换 | 各状态下按钮可用性、可编辑性、页面提示 |
| 有端到端流程 | 场景法 | 主流程走通、分支、异常回退、返回后状态 |
| 有联动、显隐、默认值 | 场景法 + 错误推测 | 字段联动、默认值带入、切换后旧值是否清除 |
| 已有功能的小范围变更 | 回归选测 | 只回归改动页面与相邻功能 |

不为凑方法生成用例；同一场景被多方法覆盖时合并。

## 二、页面交互测试点

按页面逐块过一遍，缺哪块补哪块。

### 1. 表单与输入

- 必填与选填：空值提交、仅空格、只填必填。
- 格式与长度：非法格式、超长、特殊字符、复制粘贴。
- 控件类型：下拉可搜索、多选上限、默认值、日期选择、上传类型与大小。
- 状态：只读、禁用、编辑前后差异。
- 操作：保存、保存并继续、取消后是否丢弃修改。

### 2. 列表与搜索

- 默认展示：排序、列、分页大小。
- 筛选：单条件、组合条件、清空、无结果。
- 分页与翻页：跨页操作、返回列表后筛选是否保留。
- 空态与加载态：无数据提示、加载中占位、失败重试。

### 3. 弹窗与抽屉

- 打开与关闭：右上角关闭、取消、遮罩点击、Esc。
- 未保存离开：有改动时二次确认。
- 提交结果：成功后关闭并刷新、失败后保留输入。

### 4. 流程与状态

- 状态对应按钮：待提交、待审核、已审核、驳回等状态下的可见与可操作。
- 提交与审核：通过、驳回、撤回，操作后的页面状态与提示。
- 历史数据：已审核记录再次编辑时的页面表现。

### 5. 提示与反馈

- 校验提示：位置（字段下方/顶部）、内容是否说清问题、修正后是否消失。
- 成功提示：文案、消失时机。
- 失败提示：能否重试、数据是否保留。

### 6. 权限与可见性

- 入口：无权限时菜单与按钮是否隐藏。
- 数据范围：只能看到自己组织或自己创建的数据。
- 只读态：有查看权无编辑权时页面表现。

### 7. 跳转与联动

- 跳转目标与返回：返回后筛选、分页、展开状态是否保留。
- 字段联动：A 变化导致 B 显隐、必填、选项变化。
- 多端一致性：同一功能在管理端与其他端的字段与提示是否一致。

## 三、用例写法

- 标题格式：`{页面} - {功能} - {场景}`，或“在{页面}，{操作}时，应{结果}”。
- 一个场景一条，操作与预期分开写；预期必须是页面上可看到的结果。
- 反例：“验证功能正常”“页面显示正确”。
- 正例：“在客户主体维护页，结算主体留空后点击保存，提示‘请选择结算主体’，页面停留在编辑弹窗”。

禁止出现在用例节点中：

- `TC-xxx` 之类的编号；
- `【P0】`、`【一级】` 之类的优先级或级别角标；
- `追溯：BR-x`、`E-C:112-113` 之类的内部引用。

优先级只在用户要求“表格用例”时作为表格的一列，不进入标题与导图节点。

## 四、覆盖自检

生成后逐项核对，缺的补上或写进未覆盖说明：

- 每个功能的正常流程都有用例。
- 每个必填、格式、长度限制都有对应用例。
- 每个状态下的按钮可用性都有用例。
- 每个提示文案至少有触发场景。
- 每个角色差异都有对应用例（用户提供角色信息时）。
- 需求中每条明确的业务规则都能找到对应用例。

## 五、不要做的事

- 不为凑数量复制粘贴相似用例。
- 不生成用户未勾选的范围（如接口、性能）。
- 不把页面用例写成接口调用说明。
- 不用内部代号替代功能描述。
- 不臆造提示文案、跳转目标、权限差异。
