# 测试设计方法

按业务特征选方法，不按“方法全覆盖”写用例。每种方法都要落到具体字段、规则或状态，不写抽象示例。

## 一、方法选择

| 业务特征 | 使用方法 | 产出重点 |
|---|---|---|
| 输入有格式、长度、枚举、范围限制 | 等价类划分 + 边界值 | 有效/无效等价类各取代表值；边界取上点、内点、离点 |
| 多个条件组合决定不同结果 | 决策表 | 列出条件桩与动作桩，覆盖全部有效组合，无意义组合标注“不适用” |
| 有审核、发布、取消等状态 | 状态转换 | 覆盖允许的流转 + 关键非法流转 |
| 有端到端业务流程 | 场景法 | 主流程 + 备选流 + 异常流 |
| 有并发、重复提交、时序要求 | 场景法 + 错误推测 | 同时操作、连续点击、超时重试 |
| 有历史缺陷或经验型风险 | 错误推测 | 结合缺陷记录，不脱离业务空想 |

## 二、方法要点

### 1. 等价类划分

- 先按业务规则切分，一条规则一组等价类。
- 有效等价类至少覆盖一个代表值；无效等价类每类单独一条用例，便于定位失败原因。
- 一个输入框的有效类不要合并成一条“随便填个对的”。

### 2. 边界值

- 数值、长度、金额、日期、分页、批量上限都要取边界。
- 取上点（边界值）、内点（边界内代表值）、离点（边界±1）。
- 没有明确边界时先查代码常量或配置，查不到列入未确认项，不自行编造阈值。

### 3. 决策表

- 条件项写成可判定的布尔或枚举，不写“用户操作正常”这类模糊描述。
- 每个动作对应一条或一组用例，动作相同、条件不同的行可以合并。
- 条件数量过大时先按业务规则裁剪，说明裁剪依据。

### 4. 状态转换

- 状态以代码枚举或需求定义为准，不自行命名。
- 每条允许的流转至少一条正例；关键非法流转（如已发布再编辑、已取消再审核）必须有反例。
- 状态流转伴随的副作用（通知、库存、账务、日志）要单独验证。

### 5. 场景法

- 主流程：一次走通、无中断。
- 备选流：分支条件改变走向，但业务仍可完成。
- 异常流：失败、中断、回退、补偿，验证数据是否一致。
- 每个场景写清起点、关键节点和最终状态。

### 6. 错误推测

- 依据：历史缺陷、线上问题、同模块易错点。
- 不写无业务依据的“假如数据库挂了”这类泛化用例；要写成可触发的具体操作。

### 7. 回归选测

变更类需求用它，不重写全量用例。

- 一级：直接改动的接口、页面、字段，必测。
- 二级：同链路上下游——调用方、被调用方、消息消费、定时任务、导出与报表。
- 三级：共用能力——公共组件、工具类、字典枚举、权限配置。
- 每条回归用例标注影响级别和来源（提交、文件、接口），便于判断能否裁剪。
- 影响面没有证据时不扩大猜测范围，写“影响面待确认”。

## 三、常用场景速查

| 类别 | 必须考虑的点 |
|---|---|
| 文本输入 | 空、纯空格、首尾空格、最大长度、最大+1、全角/半角、中文、特殊字符、SQL/XSS 关键字、富文本粘贴 |
| 数值/金额 | 0、负数、小数位、精度、最大值/最小值、超出上限、科学计数法、千分位 |
| 日期时间 | 起止边界、跨天/跨月/跨年、闰年、非法日期、时区、结束早于开始 |
| 下拉与枚举 | 默认值、全部枚举、失效枚举值、多选数量上限 |
| 文件 | 空文件、超大、1 字节、扩展名不符、双扩展名、路径穿越、并发上传 |
| 列表与分页 | 空列表、单条、整页、跨页操作、排序、筛选后翻页、导出全部 |
| 权限 | 无权限入口隐藏、越权直接调接口、数据行级权限、跨租户访问 |
| 并发与幂等 | 重复点击、重复提交、并发修改同一条数据、超时重试 |
| 导入导出 | 模板校验、部分失败、必填缺失、超量、编码、特殊字符、导入后数据一致性 |

## 四、优先级

| 级别 | 定义 | 适用 |
|---|---|---|
| P0 | 冒烟：失败即阻塞主流程 | 主流程、核心规则、资金与权限 |
| P1 | 主要路径，必须通过 | 常规分支、关键校验 |
| P2 | 重要但可延后 | 异常分支、边界、兼容 |
| P3 | 边缘场景 | 极端输入、低频组合 |

## 五、编号与追溯

- 用例编号：`TC-{模块}-{序号}`，如 `TC-ORDER-001`；同一交付物内唯一。
- 追溯列写需求条款号、规则 ID、接口路径三者之一，不写“见需求文档”。
- 用例名称写“对象 + 动作 + 预期”，如“必填金额为空时提交被拦截”。

## 六、不要做的事

- 不为凑方法或数量生成用例；两方法覆盖同一点时合并。
- 不写“验证功能正常”“页面显示正确”这类无法判定的预期结果。
- 不用覆盖率百分比替代覆盖清单。
- 不把测试步骤写成操作手册式长文；步骤以能复现为准。
