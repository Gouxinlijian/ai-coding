# 输出模板

只输出用户确认的格式与范围。模板中的章节按实际内容取舍，但不得留空章节或 `{{占位}}`。

## 一、文件与命名

| 项 | 规则 |
|---|---|
| Markdown 路径 | 默认 `docs/local/{业务范围}/{需求名}-测试用例.md`；项目已有用例目录或任务交付目录时按其实际结构落盘（示例：`docs/testcase/`、`docs/ai-tasks/{任务ID}/`） |
| 版本文件 | 同名已存在时改为 `{需求名}-测试用例-v{MMdd_HHmmss}.md`，不覆盖旧文件 |
| XMind 路径 | 与 Markdown 同目录同名，扩展名 `.xmind`；项目有独立用例目录时与 md 放同一目录 |
| 标题 | 文档首行 `# {需求名} 测试用例` |
| 语言 | 中文；字段名、接口路径、状态码保留原文 |
| 模块标注 | 跨模块交付时，用例编号和追溯列带模块前缀或模块名 |

## 二、文档头

```markdown
# {需求名} 测试用例

## 基本信息

| 项 | 内容 |
|---|---|
| 需求来源 | {文档标题/链接、接口文档、代码模块} |
| 需求版本 | {版本号或变更说明} |
| 测试范围 | {用户确认的覆盖范围} |
| 用例粒度 | {表格用例/测试点清单} |
| 生成日期 | {YYYY-MM-DD} |
| 证据来源 | {知识库/代码/文档，逐项列出} |
```

## 三、模板 A：表格用例

```markdown
## 一、{功能模块}

### 1.1 {子功能}

| 用例ID | 用例名称 | 优先级 | 前置条件 | 测试步骤 | 预期结果 | 追溯 |
|---|---|---|---|---|---|---|
| TC-XXX-001 | {对象+动作+预期} | P0 | {数据与状态前提} | 1. {步骤}<br>2. {步骤} | {可判定的结果} | BR-01 |
```

- 前置条件写数据与环境状态，不写“系统正常”。
- 步骤按可复现顺序编号，一条步骤只做一件事。
- 预期结果写界面可见结果、数据落库结果、消息或账务结果，能判断通过与否。
- 同一模块内先排 P0，再排 P1，依此类推。

### 精简断言表（用户要求从简时）

```markdown
| 用例 | 断言 |
|---|---|
| {操作与输入} | {可判定的结果} |
```

适合在任务目录或评审记录中快速核对；用例编号、追溯信息可省略，但断言仍须可判定，不写“功能正常”。

## 四、模板 B：测试点清单

```markdown
## 一、{功能模块}

### 1.1 {子功能}

#### 1.1.1 {功能点}

- **测试点：{验证目标}**
  - [ ] {具体验证项}
  - [ ] {具体验证项}
```

- 验证项必须是可勾选的单一事实，不写“测试 XX 功能”。
- 勾选框统一 `[ ]`，不使用 `[x]`。
- 层级固定为：模块 → 子功能 → 功能点 → 测试点 → 验证项。

## 五、模板 C：接口用例（选了接口范围时）

```markdown
## 二、接口用例

| 用例ID | 接口 | 方法 | 请求参数/体 | 前置数据 | 预期状态码 | 预期响应 | 追溯 |
|---|---|---|---|---|---|---|---|
| TC-API-001 | {路径} | POST | {关键字段与取值} | {数据要求} | 200 | {code/关键字段} | {接口文档} |
```

请求体只列关键字段与本次取值，不贴完整报文。

## 六、模板 D：XMind 结构

从 Markdown 转换时保持以下层级，转换后不手工再造第二套结构：

```text
{需求名} 测试用例
├── 一、{功能模块}
│   ├── 1.1 {子功能}
│   │   ├── TC-XXX-001 {用例名称} [P0]
│   │   │   ├── 前置条件：...
│   │   │   ├── 步骤：...
│   │   │   └── 预期：...
├── 覆盖清单
└── 未覆盖与待确认
```

- 表格行默认展开为节点：首列作为节点标题，其余列作为 `列名：值` 子节点，表头与分隔行不生成节点。
- 只想保留标题与列表时加 `--tables skip`；覆盖说明类表格不需要进导图时同样用它。
- 只交付 xmind 时，仍先生成一份临时 Markdown 再转换，便于排查；交付说明中给出临时文件位置或说明已清理。

### 转换命令

```bash
python {SKILL_DIR}/scripts/md_to_xmind.py <input.md> <output.xmind> "{需求名}" --tables expand
```

转换后报告节点总数；失败时原样给出错误输出，保留 Markdown，不声称已生成 xmind。

## 七、覆盖说明

交付物末尾固定包含：

```markdown
## 覆盖说明

| 覆盖对象 | 已覆盖 | 说明 |
|---|---|---|
| 功能点 | {列表或数量} | |
| 业务规则 | BR-01, BR-02 | |
| 状态流转 | {列表} | |
| 异常分支 | {列表} | |

## 未覆盖与待确认

| 项 | 原因 | 建议 |
|---|---|---|
```

没有未覆盖项时写“无”，不删除该章节。
