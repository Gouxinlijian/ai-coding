# 产出确认提问单

## 提问规则

- 用当前环境的选择题能力分批提问（没有就用编号列表让用户回复编号），一次 1～4 题；每题 2～4 个选项，选项带一句说明。
- 最多 2 轮；第二轮只问影响产出且第一轮未覆盖的项。
- 需求文档永远是第一件事，没有文档不进入其他问题。
- 用户回答“你决定/随便/都行”时采用本文件默认值，并在交付说明中写明。
- 不把“全部都要”作为默认勾选；范围类问题用多选，格式类问题用单选。

## 第一轮

### Q1 需求文档（必问，不可跳过）

先直接索要，不给选项：

> 请提供本次需求文档：文件路径、在线文档链接，或直接粘贴正文。没有需求文档的话，请至少给出涉及哪些页面、每个页面要做什么。

- 三种来源只接受文件、链接、正文；链接读取失败时要求用户提供正文或截图。
- 只给一句“做个 XX 功能”时，追问页面与交互细节，或说明无法生成。
- 拿到文档后先复述页面与功能清单，请用户确认，再问下面的问题。

### Q2 测试范围（多选）

| 选项 | 说明 |
|---|---|
| 页面功能与交互（默认） | 字段、控件、按钮、弹窗、列表、搜索、提示、跳转、权限可见性 |
| 接口层 | 请求路径、入参出参、状态码、幂等、异常码；大多数场景不需要 |
| 兼容 | 浏览器、分辨率、终端、系统版本 |
| 性能 | 响应时间、并发、大数据量 |
| 安全 | 越权、敏感信息展示、脱敏 |

用户未勾选的范围不生成用例，也不在交付物中保留占位章节。

### Q3 输出格式（单选）

| 选项 | 说明 |
|---|---|
| XMind（默认） | 交付 `.xmind` 导图，按页面 → 功能 → 场景展开，便于评审 |
| Markdown | 交付 `.md` 文件，便于版本管理与协作 |
| 两者都要 | 先生成清单式 Markdown 再转 xmind，内容一致 |

### Q4 交付位置（单选）

| 选项 | 说明 |
|---|---|
| `docs/local/{业务范围}/`（默认） | 业务范围按需求所属领域命名，与项目实际业务一致 |
| 项目已有用例目录 | 沿用项目现有的测试用例存放目录（示例：`docs/testcase/`） |
| 项目任务交付目录 | 项目按任务、需求单或迭代管理交付物时，跟随该任务目录（示例：`docs/ai-tasks/{任务ID}/`） |
| 指定目录 | 用户给出路径，写入该路径 |
| 直接输出到对话 | 不落盘，只在对话中给出用例正文 |

## 第二轮（按需，只问缺失项）

| 问题 | 触发条件 | 提法 |
|---|---|---|
| 用例粒度 | 用户需要执行跟踪或缺陷管理 | 需要“功能场景清单”（默认，适合评审与导图），还是“表格用例”（含步骤与优先级列）？ |
| 范围边界 | 需求没说做到哪里 | 本期明确不做的部分有哪些？ |
| 角色权限 | 涉及多角色或数据范围 | 涉及哪些角色？页面入口和只读态有差异吗？ |
| 测试环境 | 用例需要在特定环境验证 | 在哪个环境验证？有无测试账号？ |
| 历史用例复用 | 该模块可能已有用例 | 是否已有用例？合并更新还是重新生成？ |
| 变更影响面 | 需求是改已有功能 | 这次改了哪些页面？需要回归哪些相邻功能？ |

## 不该问的问题

- 需求文档里已经写清楚的内容。
- 技能内部约定：节点层级、文件命名格式、导图结构。
- 与本次交付无关的技术实现、排期、环境细节。
- 用户已经明确表达过的偏好，不重复确认。
